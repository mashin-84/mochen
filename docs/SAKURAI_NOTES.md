## 一、跟我們最相關的原則（已改寫）

### A. 頓幀與手感（#003、#047、#019、#253）
- 頓幀一定要有；**被打的一方抖大、出手的一方抖小**，只動畫面、不動判定。地面只橫抖，空中加縱抖；幅度由大收斂到小。
- 頓幀長度 ＝ 攻擊力 × 招式係數（重招、刀尖、千鈞一擊要比輕刀長）。
- Boss 倒下、主角落敗的瞬間也要短暫停格＋閃光，讓玩家意識到「我贏了／我被打倒了」。
- 直線移動、繞中心旋轉的物件很機械 → **把顯示位置或旋轉軸稍微偏一點**（飛劍、投射物晃一下、轉軸不在正中）。
- 鏡頭拉得越遠，震動幅度要越大才看得到。
- **墨塵傳現況**：v0.8.237 已做頓幀微震（`hsShake`，受擊 7px／出手 2px，可在調參面板改）；頓幀長度已有 `hitstopByDmg`；震屏是 trauma 制（`addTrauma`）。

### B. 動作與姿勢（#036、#049、#062、#077、#148、#028、#140、#223）
- 攻擊分四段：**待機 → 起手 → 出手 → 收招（follow-through）**。待機姿勢是一切的原點，先定下來不要再晃。
- **起手要「瞬間、極端」**：第 1 格就大幅換姿勢讓人看出「他要出招了」；蓄力可以長，**揮下要一瞬間**（1 格揮完），中間格少用。
- 留在玩家眼裡最久的是**命中瞬間（頓幀中）的那一格**：遠看也懂、越過身體中線、不左右對稱、身體微扭、**側視剪影要漂亮**。
- **收招顯示時間最長，決定招式印象**：攻擊判定在整招的前 1/3～1/4，後面都是破綻。強招一定要有長收招（＝玩家的反擊窗口）；收招要看得出「剛剛做了什麼」，撐到最後再回待機。
- 動作要「做過頭才剛好」，畫面越小、角色越遠越要誇張；表情也要比「已經很用力」再多一段。
- 受擊第 1 格要跟待機完全不同的「痛」姿勢；依受擊位置與輕重分幾種反應。
- 攻擊判定可以比武器外形寬一點（打不到是壓力）；但動作軌跡本身不能偏。
- **墨塵傳對應**：這幾條直接寫進**生圖關鍵格提示詞**（起手格要極端、命中格要剪影清楚、收招格要有餘韻）；程式只做輕微 `dfm`（CLAUDE.md 規定），要誇張就生圖。

### C. 特效（#016、#130、#056、#103、#221、#177、#035、#199）
- **只靠加亮（加法混色）的特效會糊**，在亮背景上幾乎看不見 → 以「畫清楚的形狀」為主，加亮為輔，**一定要混一點深色**。
- 命中特效 7 條件：跟效果相稱、對比鮮明、從判定重疊處冒出、多元素（衝擊波＋火花＋碎屑）、不遮住角色、早點消失、**亮暗背景都要看得到（加深色、墊黑）**；頓幀時特效要繼續動。
- 爆炸分段：**閃光 → 爆焰 → 黑煙 → 收束**；太短沒手感。
- 震屏大中小要換「抖法」而不只是幅度（小＝只縱抖、中＝加橫抖），先強後收、帶一點亂數。
- 全畫面白閃會降低對比、看久就麻木 → **亮暗交替**；鏡頭越近越弱。角色閃色表狀態（無敵＝白）。
- 刀光（風切り）有沒有，手感差很多；依武器個性改形狀與顏色（雙劍＝細快、重劍＝粗暴）。
- 特效不能把角色埋掉；2D 用繪製順序或描邊讓角色浮出來。
- 特效尺寸要對：劍上的火別像蠟燭。
- **墨塵傳對應**：我們的特效是「黑底生圖＋`lighter` 疊加」，本身就偏「只加亮」→ 在淡彩亮背景（竹林、雪地）會淡。改善方向見第三節 C1、C2。

### D. 遊戲性（#006、#191、#236、#245、#105、#217、#211、#116）
- 遊戲性＝風險換報酬，兩者要**放得近、大小相稱**。完美招架（高風險）報酬要明顯大於瞬步（低風險）——千鈞一擊「瞬步閃過無獎勵」就是照這條。
- 「玩家做了多好的事」決定報酬與懲罰的大小；破綻大的招要給相稱的威力。
- 調平衡別一直削強補弱（會全部變平庸）：**長處拉高、短處也拉長**；要削就改後搖、範圍、發生，別動招牌威力。
- 每個 Boss 要能用一句話講出特色（我們 `docs/DESIGN.md` 的設計卡就是這個）。
- 難度別一路直線上升：難關與平地交替；Boss 是「要玩家想攻略法的難題」。
- 攻略法太單一會有教學感；全自由又少了發現的樂趣——每關決定走哪種。
- 卡關到過不去最糟：連輸幾次可提示降難度或給輔助，但不要讓玩家覺得被羞辱。
- **重試要快**：被打倒到能再操作的時間越短越好（我們 1.9 秒，OK）；倒地演出短而華麗。

### E. 節奏、教學、獎勵（#073、#085、#171、#104、#095、#233、#178、#209）
- **慢就是罪**：等待、淡入淡出、黑幕、不能操作的時間都要壓短。
- 教學溶進實戰，不要長篇說明；複雜操作要在設計上就安排學習方法。
- **按了沒反應的按鈕不能存在**（演出中按鍵至少要有回饋或顯示「跳過」）。
- 做了好事要被誇：完美招架、全擋大招要有讚美演出（不只數字）。
- 開場直接給高潮；演出、對話一定能跳過、能暫停，最好能逐句跳。

### F. 聲音（#032、#165、#054、#202、#069）
- 音效依「對玩家影響多大」排優先順序（大亂鬥：擊墜 ＞ 命中／完美防禦 ＞ 必殺／語音 ＞ 爆炸 ＞ 迴避 ＞ 揮空 ＞ 跳躍落地 ＞ 腳步 ＞ 環境音）。**不是看音量大小調**。
- 命中音**起音要強、殘響適度**；重擊的主要聲音最好在頓幀內就結束。
- 要在多種環境聽：耳機、手機喇叭（低音會不見）、小音量。
- 環境音優先度最低但不要全靜音（停手時才有氛圍）。
- **墨塵傳對應**：我們音效正規化到 -1.5 dBFS 是「每個一樣大」，缺少依優先度的混音層級 → 第三節 F1。

### G. 畫面（#030、#241、#010、#063、#213）
- **有判定的東西（地面、平台）要醒目**，沒判定的背景要退後（空氣遠近）——第 4～9 關的平台要檢查。
- 角色靠剪影立起來：塗黑也認得出是誰。
- 畫「打在東西上的光」，不是物體本色；越遠越有空氣感（我們的淡彩薄霧風格本來就符合）。
- 最後要看整體畫面（調色、後製），不只看單張角色。

### H. 調整與除錯（#046、#193）
- 數值不要寫死在程式裡，要能在執行中一鍵改、立刻看效果；**試的次數決定調整深度**。
- 準備除錯模式（指定血量、停格、換角、看判定）；好用的除錯功能可以變成正式功能。
- **墨塵傳現況**：v0.8.237 已做「齒輪 → 🎚 手感調參」（`src/12_tune.js`），齒輪「大招測試」已有。

## 二、檢查清單（做新招、新關時逐項看）

**招式／Boss**
- [ ] 起手第 1 格就看得出要出招（姿勢極端，或有前搖預警）
- [ ] 命中格剪影清楚、越過中線、不對稱
- [ ] 收招夠長，玩家看得出是反擊機會；強招收招更長
- [ ] 頓幀長度跟招式重量相稱；重招有受擊方微震
- [ ] 風險／報酬：完美招架的報酬 ＞ 瞬步 ＞ 普通格擋；破綻大的招威力相稱
- [ ] 這隻 Boss 能用一句話講出特色

**特效**
- [ ] 亮背景（竹林、雪地）上看得到——有深色成分或描邊
- [ ] 從命中點冒出、多元素、很快消失、不遮住角色
- [ ] 帶 `facing`、尺寸跟角色比例對

**聲音**
- [ ] 依優先度分層（見 F），命中音起音強、殘響短
- [ ] 手機喇叭小音量也聽得到關鍵音（招架、危招前搖）

**節奏／UI**
- [ ] 提示一句話講完（招式名＋關鍵字），細節靠實戰教
- [ ] 沒有「按了沒反應」的時候；演出可跳過
- [ ] 重試到能操作 ≤ 2 秒
